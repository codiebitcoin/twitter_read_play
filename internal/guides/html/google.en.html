What we actually applied (project fortest)

Project name fortest, project ID gen-lang-client-0945395730. Use your own project if you prefer — the steps are the same.

  1. Sign in to Cloud Console with your own Google account (this run used you@example.com).
  2. Select project fortest.
  3. APIs & Services → Library: enable YouTube Data API v3. The success toast mentions youtube.googleapis.com.
  4. Google Auth Platform → Branding: app name Codie Live Chat (shown on the consent screen); user type External; publishing status Testing; contact email = the signed-in account.
  5. Clients → Create client → Web application:
    • Authorized JavaScript origins: {{BASE}}
    • Authorized redirect URIs: {{BASE}}/api/livechat/oauth/google/callback
    Client ID / Secret appear once in the dialog — paste them into this Live page immediately. Do not commit them.
  6. Data Access → Add or remove scopes: tick the two rows below, click Update, then Save. Success toast: data-access changes saved.
  7. Audience stays in Testing. Add the Google account that will click Allow as a test user. The branding contact is sometimes already listed; adding the same address in another case may say “not eligible” — ignore that.
  8. Back here: paste Client ID / Secret → Sign in with Google → pick the account → Allow “view your YouTube account + email”.
  9. The page shows ✓ email. New youtube_api sources can leave token / API Key empty and reuse this login.

How to enable permissions

Where: Auth Platform → Data Access. The new console no longer uses the old “OAuth consent screen” wizard.

https://www.googleapis.com/auth/youtube.readonlyRead the live stream and liveChatMessages (pull chat).
https://www.googleapis.com/auth/userinfo.emailShow which Google account signed in.

Enable YouTube Data API v3 first. Authorizing a disabled API fails later with 403 SERVICE_DISABLED.

Addresses to paste into the Google console

JavaScript origin: {{BASE}}

OAuth callback: {{BASE}}/api/livechat/oauth/google/callback

Must match the browser origin character-for-character (scheme, host, port, path). Locally this is often http://127.0.0.1:8088 — do not swap in localhost or drop the port.

Don't skip these

  • External + Testing: only test users can Allow; the refresh token expires in about 7 days and needs a fresh sign-in.
  • The Go process talking to oauth2.googleapis.com / youtube.googleapis.com often needs the system proxy. On macOS that is commonly 127.0.0.1:7892. Start the server with HTTPS_PROXY=http://127.0.0.1:7892, otherwise token exchange dies with context deadline exceeded. A working browser session does not mean the Go process can reach Google.
  • Tokens live in the SQLite blob livechat_oauth.json. Do not commit the data directory.
  • Sign-out clears tokens only; Client ID / Secret stay.
  • An API Key (Credentials → API key) also works without sign-in; default quota is 10k units/day and polling burns it quickly.
